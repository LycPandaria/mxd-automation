# MXD Automation

MXD怀旧服自动化辅助工具。基于 YOLO 目标检测 + 反应式决策引擎，实现自动打怪、加血、加蓝、同平台追击、攀爬绳索。

## 架构

三层架构，职责分离：

```
┌──────────────────┐    ┌──────────────────────┐    ┌──────────────────┐
│  感知层           │ →  │  决策层               │ →  │  执行层           │
│ YOLO 目标检测     │    │  DecisionEngine      │    │  ActionExecutor  │
│ HP/MP 颜色检测    │     │  反应式决策 + FSM     │    │  键盘/鼠标注入     │
│ YOLO 玩家定位     │     │  同平台追击/攀爬/探索  │     │  按键冷却控制      │
└──────────────────┘    └──────────────────────┘    └──────────────────┘
```

- **感知层** (`src/perception/`)：只负责"看"，输出结构化数据
  - `screen_capture` — 高性能窗口截图（Win32 `PrintWindow`）
  - `yolo_detector` — YOLO 目标检测（玩家、怪物、地板、绳索）
  - `hp_mp_detector` — 血/蓝条百分比检测（颜色数像素 + 边缘检测）
  - `template_matcher` — 模板匹配（预留）

- **决策层** (`src/decision/`)：只负责"想"，输出动作指令
  - `context` — 共享上下文 + 反应式决策引擎（同平台追击/攀爬/下落/探索/技能）
  - `fsm` — 有限状态机（IDLE / CHASING / ATTACKING / CLIMBING / DROPPING / HEALING / RECOVERING）
  - `distance` — 路径距离推算器（同层判定、绳索路径、平台跳跃路径）

- **执行层** (`src/execution/`)：只负责"做"，模拟人类操作
  - `keyboard_controller` — 键盘模拟（SendInput 真实按键 / PostMessage 后台注入）
  - `mouse_controller` — 鼠标模拟（PostMessage 注入）
  - `action_executor` — 动作执行器（聚合键鼠，带冷却控制）

## 核心流程

### 反应式决策（每帧）

```
截图 → YOLO 检测 → 按类别过滤（玩家/怪物/地板/绳索）
  → HP/MP 检测 → YOLO player 自身定位
  → 组装 Context → DecisionEngine.decide()
```

决策优先级从高到低：
1. HP 低于阈值 → 加血
2. MP 低于阈值 → 加蓝
3. 检测到怪物 → 同平台走过去攻击 / 攀爬绳索 / 跨平台跳跃
4. 没怪 → 往一个方向探索移动

### 战斗流程

```
YOLO 检测到怪物 → 筛选同平台怪物（脚底 Y 差 ≤ attack_range_y）
  → 选最近目标 → 按住方向键走过去
  → 进入攻击范围 → 松开方向键，调整朝向 → 轮转释放技能
  → 怪物死亡/消失 → 自动换下一只
```

### 转向（朝向）

转向由 `DecisionEngine._face_step` 统一处理（修复"对着没有怪物的方向放技能"）：

1. **转向单独占一帧**（那一帧不按技能键）：游戏会忽略攻击动画期间的按键
   （buff 施法窗口用的就是这条结论），转向键和技能键挤在同一帧的 30~90ms
   短按很容易被吞掉。
2. **方向键按住 120~200ms 再抬起**（不是短按），确保被游戏采样到。
3. **定期重申 + 生效自检**：攻击中每 0.6~1.2s（随机抖动）重申一次朝向，
   并用"角色有没有朝该方向动几像素"判断此次按键是否被游戏接收；没接收就
   提前重试并打日志。一次被吞掉的转向最多 1 秒左右自愈——修复前是
   "以为朝向对了、实际反向输出"能持续十几秒（因为 `_face_dir` 只在按下键时
   更新，且朝向"认为"正确后就不再按方向键）。

另外两个兜底：

- **站定期间补发方向键 KEYUP**：若某次 KEYUP 没被游戏收到（游戏侧一直"按住"
  某个方向），角色会莫名持续走、朝向固定错；检测到"无按键却持续漂移"或站定
  超过 1 秒就补发一次左右键释放。
- **防落崖**：转向会让角色朝该方向迈几像素，正前方很近处没有地板时跳过转向。

日志里每 30 帧有一条朝向自检行，用来确认朝向记忆与目标是否一致：

```
[朝向自检] 朝向记忆=right 目标在右(dx=+147px) 近30帧转向2次(自检未生效0次)
```

出现「目标在右 + 朝向记忆=left + 转向 0 次」这类组合，说明朝向记忆与游戏内
朝向脱钩（重申机制应在 1 秒内纠正）；若"自检未生效"次数持续增长，说明转向
按键一直被游戏吞掉，需检查游戏是否处于攻击动画锁定 / 窗口是否在前台。

### 近身击退（长手）

怪贴到「触发距离」以内时，改放击退技能把它推开，推开后继续站定输出——用来
顶替"贴脸就往后走"的移动型后撤：不移动（不落崖、不走进怪群、不用再走回目标），
而且击退技能本身带伤害，而后撤期间是纯输出损失。原有「贴脸后撤」
（`attack_min_range`，默认关闭）仍保留，作为击退不可用时的兜底。

配置在界面「战斗设置 → 近身击退」，也可直接改 `config/user.yaml`：

```yaml
knockback_skill:
  name: 退魔箭
  key: '3'        # 留空 = 不启用（关闭时行为与之前完全一致）
  cooldown: 0.3   # 两次击退之间的最小间隔（秒）
  range: 240      # 触发距离：角色与怪中心 x 差小于此值（同 attack_range 口径）
```

行为要点：

- **只吃掉一帧**：真按出击退键的那一帧不再放普通技能；冷却期内照常走普通技能
  选择。所以击退被游戏吞掉 / 对怪免疫（boss）/ 怪没被推开时，普通攻击都不会
  被挡住——也就不需要追踪"有没有推开"：怪被推开后 dx 自然变大，下一帧就落回
  普通攻击逻辑（每帧重新决策本身就是闭环）。
- **只长手(远程)生效**：短手（近战）的目标就是贴近怪，把怪推开是反效果。
- **转向优先**：需要转身时那一帧只转身；刚按过转向、还没确认生效的 0.35s 内
  不按击退（击退有方向，朝旧朝向放等于白放）。
- **不移动**：全程原地，不会因为击退而走位或落崖。
- 触发距离参考实测：`test/mxd_20260923_123454_*`、`test/mxd_20260923_123633_*`
  两张参考帧里，角色朝向侧最近的同平台怪分别在 224px / 232px（对应精灵框间隙
  115~118px），默认取 240（击退后怪仍落在 400px 弓射程内，不用追）。
- 日志：`[击退] 怪近身 dx=180px < 240px，按 退魔箭(3)`，用它核对触发频率与
  实际距离，再决定要不要调 `range`。

### 自身定位

**YOLO player 检测**（唯一方案，不再使用 OCR）

- YOLO 检测出画面中的 `player`（玩家）框
- 脚底 = player bbox 底部中点（`y + h`），角色中心 = bbox 中心点（`y + h//2`）
- 多人同屏时区分"自己"：
  - 有历史位置 → 取离上一帧脚底最近的 player（位置连续性）
  - 无历史位置（启动/换图）→ 取面积最大的 player（兜底启发式）

## 配置

双层配置策略：

- `config/user.yaml` — 用户运行时配置
- 内置默认值 — 未配置的字段使用代码内置默认值

坐标自适应：HP/MP 区域参数按参考分辨率 (1366×768) 配置，运行时根据实际窗口尺寸自动缩放。

### 关键配置项

下表覆盖 `config/user.yaml` 的全部字段（按用途分组）。**「默认值（当前值）」列中括号内
是本机 `user.yaml` 当前取值**，未标注括号说明与代码默认值相同。界面能改的项建议在
界面改（HP/MP 区域用框选、数值用微调框），改完会自动写回 `user.yaml`。

## 使用操作

### 第 1 步：启动程序

```bash
python main.py
```

启动后看到 **MXD 游戏辅助控制台** 窗口，界面分为三部分：

| 区域 | 内容 |
|------|------|
| 顶部 | 游戏窗口锁定（下拉选择 + 刷新 + 锁定） |
| 左侧 | 实时预览（YOLO 检测框叠加） + 开始/停止按钮 + 日志 |
| 右侧 | 配置面板（检测设置 / 血量 / 蓝量 / 战斗设置） |

### 第 2 步：锁定游戏窗口

1. 确保游戏已启动，窗口标题为 `冒险岛怀旧服`（或其他你在配置中设置的名字）
2. 点击顶部 **「刷新列表」** 按钮，下拉框会自动列出所有可见窗口
3. 在下拉框中选择游戏窗口，点击 **「锁定窗口」**
4. 锁定成功后顶部状态变为绿色 **「已锁定: 冒险岛怀旧服」**

### 第 3 步：配置检测参数

**检测设置（YOLO）**：

| 配置项 | 说明 | 操作 |
|--------|------|------|
| 模型/EXE路径 | YOLO 模型文件 | 点击「浏览」选择 `.onnx` 模型文件 |
| 置信度 | 检测阈值，越高越严格 | 拖动滑块，建议 0.5~0.8 |
| 玩家类别 | 自身定位用的类别名 | 默认 `player`，多个用逗号分隔 |
| 怪物类别 | 要检测的类别名 | 默认 `monster`，多个用逗号分隔 |
| 检测FPS | 每秒检测帧数 | 建议 1~15，性能不足可降低 |

### 第 4 步：标定 HP/MP 血条区域

**这是首次使用必须完成的步骤**，否则无法自动加血加蓝。

1. 确保游戏窗口**在前台可见**，血条/蓝条完整显示
2. 点击左侧 **「框选血条区域」** 按钮
3. 在预览画面中用鼠标**拖拽框选红色血条区域**（建议框选满血时血条前端一小段，颜色最纯）
4. 松开鼠标后程序自动识别区域颜色，右侧「血量设置」栏会显示颜色色块和坐标
5. 同样操作点击 **「框选蓝条区域」** 标定蓝色蓝条
6. 在右侧「血量设置」/「蓝量设置」中设置：
   - **按键**：加血/加蓝的快捷键（如 `f` 加血、`g` 加蓝）
   - **阈值%**：血量/蓝量低于此百分比时触发（如 50 表示低于 50% 就加）

> 标定后点击右下角 **「保存配置」**，下次启动无需重新标定。

### 第 5 步：配置战斗参数

**战斗设置**：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 跳跃键 | `alt` | 攀爬绳索/跨平台跳跃键 |
| 攻击距离 | `200` px | 人物与怪物水平距离小于此值才触发攻击 |
| 垂直容差 | `60` px | 垂直差小于此值时即使不同层也直接攻击 |

**技能列表**：

点击 **「+ 添加」** 按钮添加技能，填写：

| 列 | 说明 | 示例 |
|----|------|------|
| 名称 | 技能名称（任意，仅用于识别） | 攻击1 |
| 按键 | 游戏内技能快捷键 | `ctrl` |
| 冷却(秒) | 技能冷却时间 | `3.0` |

添加多个技能后，程序会按顺序**轮转释放**（冷却时间到了才放）。选中某行点 **「- 删除选中」** 可移除。

### 第 6 步：开始打怪

1. 确认所有配置无误后，点击 **「保存配置」**
2. 点击左侧绿色 **「▶ 开始自动打怪」** 按钮
3. 按钮变为红色 **「⏹ 停止」**，开始自动运行
4. 左侧预览窗口会实时显示 YOLO 检测框、HP/MP 数值、自身位置（黄色圆点）
5. 底部日志会输出当前状态（攻击、移动、加血等）

> 也可以按 **F6**（默认热键）启动/停止，无需点击按钮。

### 第 7 步：停止

- 点击红色 **「⏹ 停止」** 按钮
- 或按 **F6** 热键
- 停止后所有按键自动释放，不会卡方向键

### 使用技巧

- **先在小号测试**：确认功能正常后再用于正式角色
- **调整 FPS**：如果电脑性能不足，降低「检测FPS」到 5~8 可减少 CPU 占用
- **遇到卡墙/卡平台**：手动调整一下角色位置后再启动，程序会自动恢复探索
- **游戏更新后**：如果 UI 布局变化，需要重新标定 HP/MP 区域和调整 YOLO 类别相关参数
- **不要多开**：不能同时运行多个辅助实例，也不能开着辅助时手动操作游戏

## 注意事项

### 游戏窗口要求

- **必须使用窗口模式**，不支持全屏独占 DirectX 模式。全屏模式下截图会失败（BitBlt 只能截取窗口客户区），需要改用 `mss` 或 `dxcam` 方案。
- **窗口标题**必须与配置中的 `window_title` 一致（默认 `冒险岛怀旧服`），否则程序找不到游戏窗口。
- **窗口必须保持前台激活状态**（最上层），因为冒险岛通过 `DirectInput` 读取全局键盘状态，SendInput 的按键只有窗口在前台时才能被游戏接收。运行期间不能切换去操作其他程序。
- 游戏窗口建议分辨率为 **1366×768**（参考分辨率），程序支持自动缩放适配不同分辨率，但 HP/MP 区域坐标需按参考分辨率标定。

### 分辨率与坐标自适应

- HP/MP 区域、`self_offset` 等坐标参数全部按 **参考分辨率 1366×768** 配置（代码内置默认值，可在 `config/user.yaml` 中覆盖）。
- 运行时，程序会根据实际窗口客户区尺寸自动等比例缩放坐标参数。
- 如果你的游戏窗口分辨率不同，**先用 UI 的"框选 HP 区域"功能重新标定**，程序会自动计算并保存为归一化坐标（0~1 之间），下次启动时自动适配。

### 玩家定位（YOLO player）

- 自身定位依赖 YOLO 的 `player` 类别，**无需再配置角色名字**（`self_name` 已废弃）。
- 模型必须训练出 `player` 类别（详见下方「YOLO 模型」），否则无法定位自身。
- 多人同屏时，程序会优先取「离上一帧位置最近的 player」；启动/换图时取「面积最大的 player」作为兜底。极端情况（多人扎堆、他人骑大型坐骑）可能认错，属纯 YOLO 方案的固有边界。

### HP/MP 区域标定

- 首次使用必须用 UI 中的"框选 HP 区域"和"框选 MP 区域"功能标定血条/蓝条的位置和颜色。
- 标定时确保游戏窗口处于**前台可见**状态，且血条/蓝条完整显示（未被其他窗口遮挡）。
- 如果更换装备、升级、或游戏 UI 发生变化导致血条位置/颜色改变，需要重新标定。

### YOLO 模型

- 必须提供有效的 YOLO `.onnx` 模型文件，并在配置中指定 `model_path`（可在 UI 中设置）。
- 模型文件不存在时，程序会自动回退到 **MockDetector**（模拟检测器），仅用于测试框架逻辑，不会真正检测目标。
- 模型需要支持 4 个类别：`player`（玩家）、`monster`（怪物）、`floor`（地板）、`rope`（绳索）。
- 训练方法详见 [train/README.md](train/README.md)。

### 按键模式

使用 Win32 `SendInput` API 从驱动层模拟真实全局按键。冒险岛通过 `DirectInput` / `GetAsyncKeyState` 读取全局键盘状态，**只有此模式能正常工作**。

> **重要**：游戏窗口必须处于**前台激活状态**（最上层），运行期间不能切换去操作其他程序，否则按键无法注入到游戏中。这是 SendInput 的工作机制决定的，不是程序 bug。

### Python 依赖注意事项

- **onnxruntime 必须使用 1.20.1 版本**（`requirements.txt` 已锁定）：
  - 1.28.x 与 PyQt5 在 Windows 上存在 DLL 加载冲突（报错"DLL 初始化例程失败"）。
  - 1.17.x 需要 `numpy<2`，与 `numpy 2.x` 不兼容。
- 安装依赖时请严格按照 `requirements.txt` 安装，不要手动升级 onnxruntime。

### 高 DPI 显示器

- 程序在启动时自动调用 `SetProcessDPIAware()` 设置 DPI 感知，确保 BitBlt 截图使用物理像素。
- 同时设置了 `QT_SCALE_FACTOR=1` 禁用 Qt 内部 DPI 缩放，避免 UI 坐标与截图坐标不一致。
- 如果你的显示器缩放比例 ≠ 100%，屏幕坐标、鼠标坐标、截图坐标已全部统一为物理像素，无需额外配置。

### 其他注意事项

- 程序不修改游戏内存，仅通过**键盘/鼠标模拟**操作游戏，但使用过程仍有一定风险，请自行评估。
- 建议在**小号或测试服**上先试用，确认功能正常再用于正式角色。
- 游戏更新可能导致 UI 布局变化，需要重新标定 HP/MP 区域。
- 不要同时运行多个辅助实例，避免多个程序同时操作同一个窗口导致冲突。

# 安装依赖

## 训练

详见 [train/README.md](train/README.md)。

### 数据标注

1. 将截图放入 `train/data/raw/` 目录
2. 使用 LabelImg 等工具标注，保存为 Pascal VOC XML 格式
3. 标注的 XML 文件与图片同名，放在同一目录下

类别定义（共 4 类）：`player`（玩家）、`monster`（怪物）、`floor`（地板）、`rope`（绳索）

### 自动标注

```bash
python train/scripts/01_auto_annotate/main.py
```

基于少量手动标注训练模型，自动标注剩余图片。

### 正式训练

```bash
python train/scripts/02_train_yolo/main.py
```

全量数据训练 YOLO 模型，输出 `best.pt`。
